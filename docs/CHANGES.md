# 설계와 구현의 차이

| 구분 | 처음 정한 방식 | 실제로 구현한 방식 | 변경 이유와 영향 |
|---|---|---|---|
| 데이터 | '내 기록' 항목에 고른 방법이 없음 | `SavedRecord`에 `chosenRuleId` 추가 | 설계서 ④ 화면에 "방법 고른 뒤 저장"이 있어서 고른 방법을 함께 저장해야 다시 열 때 똑같이 보인다. |
| 데이터 | 전기포트 질문: 없음 또는 "한 변 1m 미만인가요?" | "함께 버릴 소형가전이 5개 이상인가요?" | 미추홀구·연수구 공식 안내에서 소형가전의 방법을 가르는 기준은 크기가 아니라 개수(5개 이상이면 무상 방문수거)였다. 답에 따라 안내가 실제로 달라진다. |
| 데이터 | `Question`은 id·text·options | `shortLabel` 필드 추가 | "손잡이: 분리 안 됨으로 이해했어요"처럼 해석 확인 문구에 질문의 짧은 이름이 필요하다. |
| 데이터 | 답이 `unknown`이면 `when: {}` 규칙만 남음 | 매칭 로직은 그대로 두고, 의자·매트리스에는 `when: {kind: "unknown"}` 규칙을 데이터로 추가 | 규격에 따라 금액이 달라 `{}` 규칙을 두면 답을 알아도 "금액 확인 필요"가 함께 나온다. 모름일 때만 금액 범위를 보여 주려고 데이터에 넣었다. |
| 데이터 | 확인일 예시 2026-11-07 | `checkedAt`은 실제 확인한 2026-11-06 | 실제로 공식 페이지를 확인한 날짜를 적었다. |
| 기능 | `/api/interpret` 입력은 질문 텍스트·선택지·답변 | 클라이언트는 `itemId`, `questionId`, 답변만 보내고 서버가 사전에서 질문·선택지를 찾음 | AI가 받는 입력은 같다. 클라이언트가 임의의 질문을 넣어 API를 쓰는 일을 막는다. |
| 기능 | 흐름 상태 저장 방식 지정 없음 | ③→④ 상태는 주소(쿼리)에 담음 | 새로고침해도 안내가 유지되고, localStorage에는 지시서가 정한 두 키만 남는다. |
| 화면 | 설정 탭(지역 변경) | 별도 경로 없이 `/setup?change=1` 재사용 | 설계서의 화면 5개를 그대로 유지한다. |
